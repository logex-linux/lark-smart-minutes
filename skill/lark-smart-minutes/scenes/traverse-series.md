# 遍历系列纪要

循环会、站会、日会的每期智能纪要通过正文「相关会议纪要」章节互相引用，形成关键词搜索覆盖不到的图谱。目标：沿引用关系遍历一个系列的全部可读纪要。

## 引用结构

```markdown
# 相关会议纪要

<callout emoji="📌"><p><cite doc-id="<token>" file-type="docx" title="智能纪要：<同系列历史会议>"></cite></p>…</callout>
```

- 提取所有 `<cite doc-id="…" title="…">`；标题归一化（去掉结尾日期）后相同即为同系列。
- 单篇引用数可达 26 条；实测 111 条引用中 89 个文档不在关键词搜索结果内——遍历是"全部纪要"需求的必要补充。

## 有界 BFS 流程

1. 从种子纪要（搜索命中或用户指定）`docs +fetch` 读正文，提取「相关会议纪要」引用列表。
2. 对每个未访问的 doc-id：`docs +fetch --doc <doc-id> --doc-format markdown --as user`；成功则记录并按标题分类（纪要/逐字稿/其他），继续提取其引用入队。
3. **设置上限**：默认最多扩展 200 篇、3 轮；达到上限时在输出中注明"图谱未穷尽，已按上限截断"，不要静默停止。
4. 系列图谱可能跨租户增长，注意与已访问集合去重（doc-id 全局唯一）。

## 权限失败处理

- fetch 失败时进程退出码为 1，错误 JSON 在 **stderr**（成功时在 stdout）；批量脚本需同时读两个流。
- 错误码 `3380004`（无查看权限）或 `3380002`（不存在/已删除）：记录该 doc-id 与标题，跳过并继续；在最终报告中单项列出"无权限/不可访问 N 篇"。
- 不要把单篇失败当作整批失败，也不要对同一 doc-id 重试超过一次。

## 跨租户副本

同一系列在内部租户与跨租户可能各有一条引用链。以 doc-id 去重后，按标题归一化合并副本，保留有权限读取的一篇（优先内部租户），另一篇在报告中注明。

## 输出

系列汇总表：会议日期、标题、owner、租户、doc token、是否可读。对不可读的只保留标题与 doc-id。用户只要系列内某类内容（待办/决策）时，转 [extract-and-summarize.md](extract-and-summarize.md) 的批量汇总流程。
