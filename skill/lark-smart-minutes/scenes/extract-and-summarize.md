# 提取待办、决策与金句

目标：从一篇或一批智能纪要中程序化提取结构化内容并汇总。输入是 `docs +fetch` 返回的 Markdown（获取方式见 [read-note-content.md](read-note-content.md)）。

## 可提取对象与模式

| 对象 | 所在章节 | 模式 |
|---|---|---|
| 待办 | `# 待办` | `- [ ] <事项名>：<描述>（来自<提出人>）` + 行内 `<cite type="user" user-name="负责人">`（可多个） |
| 关键决策 | `# 关键决策` | `- **关键决策**：<结论>` 下挂 `**问题**` / `**讨论方案**`（bullet）/ `**决策依据**`；`---` 后 `- **其他决策**` 编号列表 |
| 金句 | `# 会议中的金句时刻` 或 `# 金句时刻` | `「引文」` 空行 `—— <点评>` |
| 章节 | `# 智能章节` | `[MM:SS](<minutes_url>?t=<ms>)  **<标题>**` + `> 本章节…` 摘要 |
| 参会人 | 头部 blockquote | `<cite type="user" user-name>` 逐个提取 |
| 会议元信息 | 头部 blockquote | `会议主题：` / `会议时间：`（含星期、GMT+08）行 |
| 封面 | `# 总结` 首个 `<whiteboard token>` | 见 read-note-content |

解析规则：

- 章节名以实际返回为准，可选章节可能缺失；缺失时不补写、不报错。
- 待办的「（来自X）」是提出人，cite 是负责人，两者都要保留。
- 引用说话人时纪要中可能显示为「说话人N」，不要强行映射到真实姓名。
- `<readonly-block type="isv">` 是占位符，跳过。

## 单篇提取输出

```markdown
## <纪要标题>
- 会议时间：…；参会人：…（N 人）
- 待办（M 条）：
  1. [ ] <事项> —— 负责人：<cite 姓名>（来自<提出人>）
- 关键决策：<结论>；依据：…
- 其他决策：…
- 金句：「…」—— …
- 章节：<MM:SS> <标题>（深链 <url>）
```

## 批量汇总

用户要求汇总多篇（一个系列、一个时间范围、一个主题）时：

1. 按 [search-and-enumerate.md](search-and-enumerate.md) 取得去重后的清单，逐篇 `docs +fetch`。
2. 逐篇提取后合并：
   - **待办总表**：按负责人分组，标注来源纪要标题与日期；同一条待办在多期例会重复出现时合并并列出各期。
   - **决策时间线**：按会议时间排序，标注每期关键决策。
   - **金句集**：按纪要分组。
3. 某篇 fetch 失败（无权限 3380004 / 不存在 3380002）时跳过该篇并在报告末尾单项列出，不中断整批。
4. 汇总基于 AI 生成内容时保留免责声明语义，注明「智能纪要由 AI 生成，可能不准确」。

## 边界

- 用户要求重新总结、复盘或争议分析时，若需原文依据，读取逐字稿后独立分析，不要把 AI 总结改写为自己的结论。
- 只提取不修改：本技能无写操作；修改妙记总结/待办属于 lark-meeting 的 minutes 域。
